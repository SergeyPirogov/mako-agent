# 🦈 Mako

**Нова задача в трекері → сповіщення на десктопі → один клік → над нею працює ваш AI-агент.**

Mako — локальний демон, який стежить за задачами в **Jira**, **GitHub Issues** і **GitLab Issues**.
Коли зʼявляється задача для агента, на десктопі виринає сповіщення **«🦈 У вас нова задача»**
з кнопками **Взяти** і **Відкласти**. Взяті задачі Mako віддає агенту на вашому компʼютері: у **вбудований термінал**,
де ви бачите Claude і можете втрутитися будь-коли, у фоновий Claude Code, Orca, Codex або будь-яку іншу команду.
Кожна задача виконується в окремому git worktree, тож ваша робоча копія лишається недоторканою.

> Mako — найшвидша акула. Помічає задачу першою і віддає її тому, хто її зробить.

## Встановлення

**Застосунок для Mac.** Завантажте з [останнього релізу](https://github.com/SergeyPirogov/mako-agent/releases/latest)
`Mako-…-arm64.dmg` (Apple Silicon, M1 і новіші) або `Mako-…-x64.dmg` (Intel) і перетягніть Mako в Applications.
Застосунок не нотаризований Apple, тому перший запуск такий: правий клік на Mako → **Відкрити** → **Відкрити**.
Або один раз у терміналі:

```bash
xattr -dr com.apple.quarantine /Applications/Mako.app
```

**Команда в терміналі (macOS, Linux).** Потрібні `git` і Node.js 22+:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyPirogov/mako-agent/main/install.sh | sh
mako
```

Скрипт кладе Mako в `~/.mako-agent`, а команду `mako` у `~/.local/bin`. Налаштування зберігаються в `~/.mako`.
Щоб оновитися, запустіть ту саму команду ще раз.

Після першого запуску Mako відкриє майстер налаштування, який крок за кроком проведе через трекер, токен,
репозиторій і агента.

**Новий реліз** (для мейнтейнерів): `npm version patch && git push --follow-tags`. GitHub Actions прожене тести,
збере `.dmg` і `.zip` для Apple Silicon та Intel і прикріпить їх до релізу.

## Можливості

> **Два режими** (Налаштування → «Режим роботи»). **Повний:** агент працює в терміналі Mako, з планом, автопілотом MR,
> шаблонами й памʼяттю. **Диспетчер для Orca:** Mako лише бачить ваші задачі в трекері, віддає їх в Orca однією кнопкою
> «Віддати в Orca» й веде їхній статус: «In progress» при передачі (і призначення на вас), коментар і статус ревʼю,
> щойно зʼявився MR, «Done» і закриття після мерджу. У диспетчері немає термінала, плану, автопілота й шаблонів;
> трекери, «Мої задачі з усіх проєктів», клонування й архів працюють так само.

- **Застосунок у рядку меню:** 🦈 біля годинника з лічильником «1/2», задачі та їхній стан у меню, власне вікно,
  сповіщення від імені Mako, пауза й автозапуск. Без застосунку Mako працює й просто як процес у терміналі.

- **Трекери на вибір:** Jira (Cloud), GitHub Issues (зокрема Enterprise), GitLab Issues (зокрема self-hosted). Можна кілька одночасно.
- **Ви вирішуєте, що брати:** нативні сповіщення з кнопками на macOS, Windows і Linux, а також локальна сторінка «Задачі» на випадок, якщо сповіщення пропущене.
- **Вбудований термінал:** агент працює в терміналі прямо у вебінтерфейсі Mako. Ви бачите кожен крок, відповідаєте на питання,
  погоджуєте дозволи. Коли агенту потрібна ваша участь, приходить сповіщення. Окремі інструменти на кшталт Orca не потрібні.
- **Не привʼязаний до інструмента:** агента запускає «виконавець», і його можна вибрати для кожного репозиторію окремо.
- **WIP-ліміт як у канбані:** наприклад, не більше 2 задач у роботі. Поки ліміт заповнений, Mako не опитує трекер.
- **Ізоляція:** окремий worktree і гілка на кожну задачу (`feature/17-add-dark-mode`, `fix/9-…`, за вашим шаблоном), кілька агентів працюють паралельно.
- **MR як в Orca:** «Створити MR» з commit message і описом, які Claude пише за змінами; статус CI з jobʼами за стадіями,
  невирішені коментарі ревʼюерів, конфлікти. Одним кліком віддати агенту «полагодь CI», «виправ коментарі», «розвʼяжи конфлікти»,
  і змерджити прямо з Mako.
- **Автопілот MR:** за бажанням Mako сам віддає фоновому агенту впалий CI, нові коментарі й конфлікти, поки MR не стане готовим,
  з лімітом раундів; може й змерджити сам.
- **Файли задачі для агента:** скриншоти й файли з опису та коментарів (GitLab, GitHub) і вкладення Jira
  Mako завантажує токеном трекера в `.mako/attachments/` робочої копії (не комітиться) і перелічує в інструкції агенту:
  Claude Code бачить картинки. До 10 файлів, кожен до 15 МБ; на картці задачі «📎 N».
- **Підсумок:** після «Завершити» Claude пише, що зроблено, як перевірено і на що звернути увагу. Відкривається з картки поруч зі змінами.
- **Маршрутизація:** одна Jira на кілька репозиторіїв, з вибором за міткою `repo:<назва>`, компонентом або правилами.
- **Повний цикл:** статус «In progress» на старті, push, PR/MR з `Closes #N`, коментар у задачі, а після мерджу статус «Done» і закрита задача.
- **Видно все, що відбувається:** опис задачі з повноцінним Markdown, поточний крок агента на картці, «Хід роботи»
  для фонових агентів, позначки «🔒 Потрібні дозволи» і «🗑 Видалена в GitLab».
- **Стійкість до перезапусків:** стан зберігається на диску, відкладені задачі не губляться, перервані повертаються в чергу.

## Як це працює

```mermaid
flowchart LR
    T[Jira / GitHub / GitLab] -- "опитування за JQL або міткою" --> M((🦈 Mako))
    M -- "🔔 У вас нова задача" --> U{Ви}
    U -- Відкласти --> M
    U -- Взяти --> R[Вибір репозиторію]
    R --> E{Виконавець}
    E -- "terminal / claude-headless / command" --> W[git worktree<br/>feature/123-…]
    W --> P[commit → push → PR/MR]
    E -- "orca / handoff" --> O[Orca, tmux, IDE:<br/>ви керуєте агентом]
    O -. "Mako помічає PR" .-> P
    P -- "коментар + In Review" --> T
```

1. Mako раз на хвилину питає трекер, чи є нові задачі для агента.
2. Про кожну нову задачу ви отримуєте сповіщення. У ньому видно, куди піде задача, наприклад `Jira → web · Claude Code`.
3. «Взяти» ставить задачу в чергу. «Відкласти» або проігнороване сповіщення: Mako спитає знову через годину.
4. Задача переходить в In Progress, Mako створює worktree від свіжого `origin/main` і запускає агента з промптом,
   зібраним із назви, опису й коментарів задачі.
5. «Створити MR» (або «Завершити») комітить, пушить гілку й відкриває MR з описом від Claude, пише коментар у задачу.
6. Поки MR відкритий, задача в колонці «На ревʼю»: видно CI, коментарі й конфлікти, агент виправляє їх за запитом.
7. Після мерджу задача отримує статус «Done», закривається і переходить у «Готово».

## Швидкий старт

**Потрібно:** Node.js 22+, `git` і агент. За замовчуванням це [Claude Code](https://docs.anthropic.com/en/docs/claude-code)
з виконаним входом. Для PR у GitHub ще потрібен `gh` з виконаним `gh auth login`.
На Linux для вбудованого термінала потрібні `make` і `g++`, бо `node-pty` компілюється при встановленні;
для macOS і Windows є готові бінарники.

```bash
git clone https://github.com/SergeyPirogov/mako-agent && cd mako-agent
npm install
npm run dev
```

При першому запуску конфігу ще немає, тож Mako відкриває **майстер** (http://127.0.0.1:7777/welcome):

1. **Перевірка:** чи встановлені `git` і Claude Code, з підказкою, як поставити.
2. **Трекер:** вставте посилання на проєкт або будь-яку задачу, і Mako сам визначить GitLab, GitHub чи Jira та адресу.
   «Створити токен» відкриває сторінку токена з потрібними правами.
3. **Задачі:** «призначені на мене» або «з міткою», і перевірка, скільки задач знайдено.
4. **Код:** Mako сам знаходить локальний клон репозиторію та його основну гілку.
5. **Агент:** термінал Mako (рекомендовано) або Claude у фоні. «Готово» — і Mako починає шукати задачі.

Усе інше (кілька трекерів, статуси, шаблон гілок, виконавці) є в **Налаштуваннях**.

Сторінка лише записує `mako.config.json` і `.env`, тож усе можна редагувати й вручну.
Повний приклад лежить у [`mako.config.example.json`](mako.config.example.json), а перевірити конфіг без змін можна так:

```bash
npm run dev -- --dry-run
```

## Застосунок у рядку меню (macOS, Windows, Linux)

```bash
npm install
npm run app          # запустити застосунок з вихідного коду
npm run app:build    # зібрати Mako.app у release/ (на Mac: release/mac-arm64/Mako.app)
npm run app:dmg      # або .dmg-інсталятор
```

Зібраний `Mako.app` перетягніть у Applications. Збірка ad-hoc-підписана без сертифіката Apple:
на вашому Mac вона відкривається без попереджень, бо зібрана локально. Якщо передаєте `.dmg` іншим,
при першому запуску треба буде дозволити його в System Settings → Privacy & Security
(або підписати й нотаризувати власним Apple Developer ID).

**Що є в рядку меню:**

| | |
|---|---|
| **Значок** | Плавник і лічильник `1/2` (у роботі / WIP-ліміт). `●` означає, що агент чекає на вас або є нова задача; `⏸` означає паузу |
| **Меню** | Задачі в роботі та їхній стан («працює», «чекає на вас», «чекає PR»); клік відкриває термінал задачі |
| | «Відкрити Mako», «Налаштування…», «Пауза: не брати нових задач», «Запускати при вході в систему», «Показати папку даних», «Вийти» |

- Mako живе лише в рядку меню, без значка в Dock. Значок у Dock зʼявляється, поки відкрите вікно.
- Закриття вікна не зупиняє Mako. Вийти можна через меню; якщо агенти ще працюють, Mako перепитає.
- Сповіщення приходять від Mako з кнопками «Взяти» і «Відкласти». Клік по сповіщенню відкриває вікно.
- Конфіг, `.env` і стан застосунку лежать у `~/Library/Application Support/Mako` (на Linux `~/.config/Mako`),
  а не в папці проєкту. Інше місце можна задати змінною `MAKO_HOME`.
- Застосунки, запущені з Finder, не бачать PATH з `~/.zshrc`. Mako бере PATH з вашої оболонки при старті,
  тож `claude`, `gh` і `git` знаходяться так само, як у терміналі.

## Життєвий цикл задачі

| Стан | Що відбувається |
|---|---|
| **Нова** | Задачу знайдено, на екрані сповіщення з кнопками |
| **Відкладена** | Ви натиснули «Відкласти» або проігнорували сповіщення. Через `snoozeMin` хвилин Mako спитає знову |
| **У черзі** | Ви натиснули «Взяти». Агент стартує, щойно звільниться слот (`maxConcurrent`) |
| **Виконується** | Задача переходить у статус `onStart` (Jira, GitLab), працює виконавець |
| **Передано** | Задачу відкрито в Orca, tmux тощо, і нею керуєте ви. Mako чекає PR/MR з гілки задачі |
| **На ревʼю** | Задачу завершено, MR відкритий і ще не змерджений: видно CI, коментарі, конфлікти, кнопки для агента й «Змерджити» |
| **Готово** | MR змерджено (статус `onMerged`, за замовчуванням «Done», задачу закрито) або задача завершилась без MR. «Підсумок» на картці |
| **Помилка** | Коментар із причиною, статус `onFailure` (якщо задано), сповіщення ❌, кнопка «Повторити». Якщо агенту бракувало дозволів, на картці «🔒 Потрібні дозволи» і «Продовжити в терміналі» |
| **Скасовано** | Ви скасували задачу в черзі чи передану, або її workspace видалили без PR. Місце в роботі звільняється, кнопка «Повторити» |

## Конфігурація

Найпростіше налаштовувати через сторінку **Налаштування** (http://127.0.0.1:7777/settings): там є всі параметри нижче,
перевірка підключення до трекера, а зміни застосовуються без перезапуску. Під капотом конфіг лежить у `mako.config.json`
(інший файл можна вказати через `-c`), секрети в `.env`.

### Загальні параметри

| Параметр | За замовчуванням | Що означає |
|---|---|---|
| `pollIntervalSec` | `60` | Як часто опитувати трекери |
| `wipLimit` | `0` (без ліміту) | Максимум задач у роботі, див. [WIP-ліміт](#wip-ліміт) |
| `maxConcurrent` | `wipLimit` або `1` | Скільки агентів працюють одночасно (стосується лише виконавців, яких Mako чекає) |
| `taskTimeoutMin` | `45` | Ліміт часу на одну задачу |
| `handoffCheckMin` | `5` | Як часто шукати PR для переданих задач, `0` вимикає |
| `stateDir` | `.mako` | Стан (`state.json`), логи агентів і промпти |
| `defaultExecutor` | термінал Mako | Виконавець для репозиторіїв без власного `executor` |
| `branchPattern` | `{type}/{id}-{title}` | Назва гілки задачі: `{type}` (`fix` для багів, інакше `feat`), `{id}` (номер або ключ Jira), `{title}` (назва латиницею), `{slug}`. Наприклад `feature/{id}-{title}` → `feature/17-rozibraty-nichnyi-ran`. Нова спроба з нуля отримує `-try2` |

### WIP-ліміт

Як у канбані: Mako тягне нову роботу, лише коли є вільне місце.

```json
"wipLimit": 2
```

- **«В роботі»** — це взяті задачі в черзі, ті, що виконуються, і передані в Orca чи tmux, поки для них не зʼявився PR.
- **Ліміт заповнений:** Mako взагалі не звертається до трекерів. Нових сповіщень немає, задачі чекають у трекері.
  Перевірка PR для переданих задач триває, бо саме вона звільняє місце.
- **Є вільні місця:** Mako пропонує рівно стільки задач, скільки місць, у порядку трекера
  (для Jira порядок задає `ORDER BY` у JQL, тож пріоритетні йдуть першими). Задача, про яку висить сповіщення, тримає місце.
  Якщо її відкласти чи проігнорувати, місце дістається наступній.
- У «Задачах» видно лічильник «В роботі: 1 / 2». Кнопка «Взяти» там працює і понад ліміт: це ваше свідоме рішення.

### Трекери

Масив `trackers` може містити кілька трекерів, зокрема одного типу. Тоді кожному потрібен свій `id`.

| `type` | Які задачі беруться | Як позначається прогрес | Ключ у `projects` | Секрети в `.env` |
|---|---|---|---|---|
| `jira` | За `jql` | Статуси з `transitions` | Ключ проєкту: `PROJ` | `JIRA_BASE_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN` |
| `github` | Відкриті issues з міткою `labels.trigger` | Коментарі; issue закривається мерджем PR (`Closes #N`) | `owner/repo` | `GITHUB_TOKEN` або `gh auth login` |
| `gitlab` | Відкриті issues з міткою `labels.trigger` | Статус задачі з `transitions` (GitLab 17.11+, Premium/Ultimate) | `group/project` | `GITLAB_TOKEN` (scope `api`) |

<details>
<summary><b>Jira</b></summary>

```json
{
  "type": "jira",
  "jql": "assignee = currentUser() AND labels = claude-agent AND statusCategory = \"To Do\"",
  "transitions": { "onStart": "In Progress", "onSuccess": "In Review", "onFailure": null },
  "projects": { "PROJ": { "repoPath": "/Users/me/code/backend" } }
}
```

`transitions` приймає назву переходу або назву цільового статусу, регістр не враховується. `null` означає не змінювати статус.
API-токен створюється на [id.atlassian.com](https://id.atlassian.com/manage-profile/security/api-tokens).
</details>

<details>
<summary><b>GitHub / GitLab</b></summary>

```json
{
  "type": "github",
  "assignee": "my-login",
  "labels": { "trigger": "claude-agent" },
  "projects": { "my-org/web": { "repoPath": "/Users/me/code/web" } }
}
```

`assignee`: ваш нік (з `@` чи без) або `me`, і тоді Mako бере нік із токена. Щоб брати всі відкриті задачі,
призначені на вас, без мітки, задайте `"labels": { "trigger": null }` (у Налаштуваннях: «Брати всі мої задачі, без мітки»);
без мітки `assignee` обовʼязковий, щоб Mako не взяв усі задачі проєкту.

Mako опитує кожен репозиторій із `projects`. Мітка `trigger` лише відбирає задачі для агента: інших міток
Mako не ставить і не знімає. Якщо потрібні мітки прогресу, задайте `labels.inProgress`, `labels.done`, `labels.failed`.

**Статуси в GitLab.** `"transitions": { "onStart": "In progress", "onSuccess": "In review", "onMerged": "Done" }` змінює статус задачі
(work item status) через GraphQL; назви без урахування регістру. Без налаштувань Mako сам ставить «In progress»
на старті й «Done» після мерджу, якщо такі статуси є в проєкті, і закриває задачу. Список статусів вашого проєкту показує
«Перевірити підключення». Статуси є в GitLab 17.11+ на Premium/Ultimate; якщо їх немає, Mako попереджає,
а задача все одно виконується. У GitHub issues статусу немає (лише відкрито/закрито): issue закриється мерджем PR.
Для GitHub Enterprise вкажіть `"apiUrl": "https://github.example.com/api/v3"`.
Для GitLab укажіть `"type": "gitlab"`, а для self-hosted ще `"baseUrl": "https://gitlab.example.com"`.
</details>

### Репозиторії та маршрутизація

Найпростіший випадок: один проєкт трекера відповідає одному репозиторію. Для GitLab і GitHub можна нічого не вказувати:

```json
"projects": { "my-org/web": {} }
```

Тоді клон живе в `~/mako/projects/web` (папка задається загальним `projectsDir`). Якщо там ще порожньо, перед першою
задачею Mako сам клонує `git@<ваш GitLab>:my-org/web.git`, без питань: потрібен SSH-ключ (або збережений пароль git).
В Налаштуваннях для цього є кнопка «Склонувати зараз». Інша адреса задається в `cloneUrl`. Базова гілка теж
визначається сама: основна гілка репозиторію (`origin/HEAD`), наприклад `main`, `master` чи `develop`.

Уже склонований репозиторій вказується шляхом:

```json
"projects": { "my-org/web": { "repoPath": "/Users/me/code/web" } }
```

Якщо в одному проєкті є задачі для різних репозиторіїв, перелічіть їх у `repos`:

```json
"projects": {
  "PROJ": {
    "default": "backend",
    "repos": {
      "backend": { "repoPath": "/Users/me/code/backend", "match": { "components": ["Backend", "API"] } },
      "web":     { "repoPath": "/Users/me/code/web",     "match": { "labels": ["ui"] }, "executor": "orca" }
    }
  }
}
```

Репозиторій вибирається за пріоритетом:

1. мітка **`repo:<назва>`** на задачі;
2. перше правило **`match`**, де збіглася мітка або компонент Jira;
3. **`default`**, або єдиний репозиторій проєкту.

Якщо репозиторій визначити не вдалося, задача не пропонується, а в лог пишеться причина.

| Параметр репозиторію | За замовчуванням | Що означає |
|---|---|---|
| `repoPath` | `~/mako/projects/<repo>` | Локальний клон; якщо його немає, Mako клонує з `cloneUrl` |
| `cloneUrl` | `git@<host>:<проєкт>.git` для GitLab/GitHub | Звідки клонувати. Для Jira не визначається: вкажіть його або `repoPath` |
| `baseBranch` | основна гілка (`origin/HEAD`) | Від якої гілки створювати гілку задачі й куди відкривати PR |
| `worktreesDir` | `<repoPath>/../.worktrees/<repo>` | Де створювати worktree |
| `pullRequest` | `auto` | `auto` (за адресою `origin`), `github` (через `gh`), `gitlab` (через git push options) або `none` |
| `executor` | `defaultExecutor` | Хто виконує задачі цього репозиторію |
| `setup` | `auto` | Команда в новому worktree до старту агента, щоб працювали тести, лінтери й git-хуки. `auto` вибирає за lock-файлом (`pnpm install --frozen-lockfile`, `npm ci`, `yarn install`, `bun install`, `uv sync`, `poetry install`, `bundle install`); `none` вимикає |
| `extraInstructions` | | Додатковий рядок у промпт, наприклад «Run `npm test` before committing» |
| `match` | | `{ "labels": [...], "components": [...] }` для маршрутизації |
| `branchPattern` | загальний `branchPattern` | Свій шаблон назви гілки для цього репозиторію |

### Виконавці

Виконавець визначає, як саме запускається агент. Опишіть один або кілька в `executors`.

| `type` | Як працює | Хто робить PR |
|---|---|---|
| `terminal` | Інтерактивний `claude` (або інший CLI-агент) у терміналі всередині Mako. Можна втрутитися будь-коли, «Завершити» закриває сесію | Mako |
| `claude-headless` | Mako створює worktree і запускає `claude -p`, чекає результату | Mako |
| `orca` | `orca worktree create --agent … --prompt …`: [Orca](https://github.com/stablyai/orca) створює workspace, ви бачите агента і керуєте ним | Ви, а Mako помічає PR |
| `command` + `"mode": "managed"` | Будь-яка CLI у worktree, Mako чекає завершення. Код `0` означає успіх, кінець stdout стає підсумком | Mako |
| `command` + `"mode": "handoff"` | Запускає інструмент і відпускає: вікно tmux, IDE, інший UI | Ви, а Mako помічає PR |

```json
"executors": {
  "terminal": { "type": "terminal" },
  "claude": { "type": "claude-headless", "args": ["--permission-mode", "acceptEdits"] },
  "orca":   { "type": "orca", "agent": "claude" },
  "codex":  { "type": "command", "label": "Codex", "command": "codex", "args": ["exec", "--full-auto", "{prompt}"] },
  "tmux":   { "type": "command", "mode": "handoff", "command": "tmux",
              "args": ["new-window", "-n", "{slug}", "-c", "{worktree}", "claude", "{prompt}"] }
},
"defaultExecutor": "claude"
```

**Вбудований термінал (`terminal`).** Mako запускає інтерактивного агента в псевдотерміналі в worktree задачі.
Сесію видно на дошці «Задачі» (кнопка «Термінал»). Вона живе далі, навіть якщо закрити вкладку, і її можна відкрити
в кількох вкладках одночасно. Для Claude Code Mako додає на час сесії хуки (через `--settings`,
ваш `~/.claude/settings.json` не змінюється) і завдяки ним знає стан агента:

| Стан | Що означає |
|---|---|
| **Працює** | Агент виконує задачу |
| **Чекає на вас** | Потрібен дозвіл або відповідь. Приходить сповіщення, клік по ньому відкриває термінал |
| **Можна перевіряти** | Агент завершив роботу. Перевірте результат і натисніть **«Завершити»** або дайте нові інструкції |

**Коли агент чекає на вас, це видно скрізь:**
- на дошці «Задачі» вгорі блок **«🔔 Потрібна ваша увага»**: що саме потрібно («Просить дозволу: Bash», «Чекає на вашу відповідь»,
  «Можна перевіряти») і як давно; сторінка оновлюється сама;
- іконка вкладки браузера стає помаранчевою, у заголовку «(1)»;
- у рядку меню помаранчевий плавник і `●`, задача піднімається вгору меню з поясненням;
- відкрите вікно Mako привертає увагу (на macOS підстрибує значок у Dock);
- сповіщення, яке повторюється кожні `notifications.remindMin` хвилин (за замовчуванням 5, `0` вимикає),
  поки ви не почнете відповідати в терміналі.

**Змінені файли.** Кнопка «Зміни» на сторінці сесії відкриває праворуч від термінала панель: список файлів
(деревом папок або списком: додано, змінено, видалено, новий незакомічений) з `+/−` рядками, коміти задачі і кольоровий diff відносно базової гілки.
Панель оновлюється сама, поки агент працює. Для будь-якої задачі з worktree, зокрема завершеної, на дошці «Задачі» є посилання «Зміни».

«Завершити» закриває агента (`/exit`), після чого Mako комітить, пушить, відкриває MR (якщо його ще немає) і пише в задачу коментар;
Claude пише підсумок, який видно з картки. Як працювати з MR до «Завершити», див. [MR](#mr-від-створити-mr-до-мерджу). «Скасувати» зупиняє агента без PR, зміни лишаються у worktree. Параметри: `command` (на Windows `claude.cmd`),
`args` (за замовчуванням `["{prompt}"]`), `autoFinish` (завершувати самостійно, якщо ви не втручались), `claudeHooks`.
Інші агенти (наприклад `codex`) теж працюють, лише без статусів «чекає» і «можна перевіряти».

**Підстановки в `command.args`:** `{worktree}`, `{prompt}`, `{promptFile}`, `{taskId}`, `{slug}`, `{branch}`,
`{title}`, `{url}`, `{repoPath}`, `{repo}`. Команда запускається без shell. Якщо shell потрібен,
читайте промпт з `{promptFile}`, а не вставляйте `{prompt}` у рядок `sh -c`.

**Orca:** репозиторій має бути доданий в Orca, а `orca` має бути в `PATH`. Mako передає гілку, базову гілку
і посилання на задачу. Додаткові параметри: `agent` (`claude`, `codex`, …), `setup` (`run` / `skip` / `inherit`),
`linkIssue`, `extraArgs`.

**Як Mako помічає PR для переданих задач.** Раз на `handoffCheckMin` хвилин Mako виконує `git ls-remote`
і шукає `refs/pull/N/head` (GitHub) або `refs/merge-requests/N/head` (GitLab), що вказують на гілку задачі.
Токени для цього не потрібні. PR знайдеться, навіть якщо Orca додала до назви гілки суфікс
(`agent/PROJ-1-2`) або гілку видалили після мерджу.

Для інтерактивних виконавців промпт трохи інший: агент знає, що ви поруч і можете відповісти на питання.

### Сповіщення

```json
"notifications": { "enabled": true, "autoTake": false, "snoozeMin": 60, "timeoutSec": 600, "inboxPort": 7777 }
```

| Параметр | Що означає |
|---|---|
| `enabled` | `false`: без сповіщень, задачі чекають на дошці «Задачі» |
| `autoTake` | `true`: брати все без питань |
| `snoozeMin` | Через скільки хвилин знову питати про відкладену задачу |
| `timeoutSec` | Скільки сповіщення чекає відповіді, після цього вважається проігнорованим |
| `inboxPort` | Порт сторінки «Задачі», `null` вимикає її |

## MR: від «Створити MR» до мерджу

На сторінці сесії, поки агент працює:

- **«Створити MR».** Незакомічені зміни Mako комітить з повідомленням, яке Claude пише за діфом, пушить гілку
  й відкриває MR. Назву й опис MR Claude пише за всіма змінами гілки; опис записується через API, тож він повноцінний,
  багаторядковий, із `Closes #N`. У задачу йде коментар з посиланням і описом змін. Агент працює далі.
- **«Оновити MR»** активна, лише коли після останнього оновлення є нові зміни.
- **Над терміналом** видно MR: CI з jobʼами за стадіями (✓ ✗ ⏳ ◷ ▶, помаранчевий «!» для дозволених падінь),
  «⚠ конфлікти», «💬 N» невирішених коментарів, «готовий до мерджу» або що заважає.
- **Кнопки для агента:** «Полагодити CI» (агент отримує jobʼи, що впали, з кінцем логів), «Виправити коментарі»
  (файл, рядок і текст кожного), «Розвʼязати конфлікти» (`git merge` основної гілки, без rebase).
  Після коментарів агент пише, що зробив у кожному треді; «Оновити MR» пушить правки, відповідає в тредах
  («🦈 Винесено в `TIMEOUT_MS`…») і закриває виправлені (у GitHub ревʼюер закриває сам). Якщо агент у терміналі,
  запит приходить туди; якщо задача вже завершена, Mako запускає агента знову в тому ж worktree лише з цим запитом.
- **«Змерджити»** зʼявляється, коли GitLab/GitHub дозволяє мердж. Після мерджу задача отримує статус «Done» і закривається.
- **«Завершити»** після MR не відкриває другий MR і не пушить, якщо нових змін не було.

Задачі з Jira, код яких у GitLab чи GitHub, теж отримують усе це: дані MR Mako бере з самого GitLab/GitHub
токеном із Налаштувань, а після мерджу переводить задачу Jira в «Done» (або в `onMerged`).

**«Взяти» призначає задачу на вас** у трекері, тож колеги бачать, що її взято, а їхній Mako її не пропонує.
Вимикається галочкою в картці трекера (`assignOnTake: false`).

Mako перевіряє відкриті MR раз на хвилину (на сторінці сесії частіше) і надсилає сповіщення, коли впав CI,
зʼявились конфлікти або нові коментарі. Ті самі дані й кнопки є на картці в колонці «На ревʼю».

### Автопілот MR

Те саме без кліків. Коли автопілот увімкнено, Mako після кожної перевірки MR сам віддає фоновому агенту те,
що заважає мерджу: спершу конфлікти, потім CI, що впав, потім нові треди ревʼюерів. Кожну річ лише раз
(той самий пайплайн чи тред не віддається вдруге), і лише коли агент вільний. Агент виправляє в тому ж worktree,
Mako пушить, оновлює MR і відповідає в тредах; новий пайплайн автопілот теж дочекається.

- **Ліміт раундів** (за замовчуванням 3): далі автопілот зупиняється, а вам приходить сповіщення.
- **Коли MR готовий** (CI зелений, коментарів і конфліктів немає, GitLab/GitHub дозволяє мердж), Mako повідомляє про це,
  а з галочкою «Мерджити самому» мерджить. Апруви, якщо проєкт їх вимагає, лишаються за людьми.
- **Для раундів потрібен фоновий виконавець** («Claude Code у фоні» чи своя команда): термінал чекав би на вас.
- **Вмикається** для всіх MR у Налаштуваннях (Задачі й ліміти → Автопілот MR) або для окремої задачі на картці
  («Увімкнути автопілот» / «Вимкнути»). Там же видно, що він зараз робить: «раунд 2/3 — лагодить CI».

```json
"autopilot": { "enabled": true, "maxRounds": 3, "merge": false }
```

## Використання

```bash
npm run dev -- --dry-run          # знайдені задачі, маршрути й промпти; нічого не змінюється
npm run dev                       # працювати постійно
npm run dev -- -c other.json      # інший конфіг

npm run build && npm link         # команда `mako` глобально
mako --dry-run
```

**Вебінтерфейс** (http://127.0.0.1:7777) має дві вкладки:
- **«Задачі» — робоче місце:** ліворуч список задач, згрупований так, що зверху те, що чекає на вас: «Потребує вас»
  (агент питає, план готовий, можна перевіряти), «Працює», «На ревʼю», «Нові», «Готово», «Не виконано» (помилки,
  скасовані й ті, чий MR закрили без мерджу); над ним перемикачі проєктів, ↑/↓ ходять списком. Праворуч вибрана задача:
  якщо агент працює в терміналі, це живий термінал (питання агента з нумерованими варіантами — кнопками під ним)
  і деталі поруч (на ноутбуці вони відкриваються поверх); інакше її дії, MR, хід роботи й повний опис.
  «Взяти ▾» і «Повторити ▾» дають вибрати, хто виконує задачу і в якому репозиторії; повтор може піти
  «з нуля в новому worktree» (для задач з MR так і за замовчуванням). Для фонового агента є «Хід роботи»
  і «Перейти в термінал» (та сама розмова продовжується в терміналі Mako).
  Задачі, видалені чи закриті в трекері, позначаються на картці. «В архів» прибирає задачу з дошки, а в Архіві
  «Видалити» прибирає її разом із worktree, локальною гілкою й журналом.
  Передану чи задачу в черзі можна «Скасувати»; якщо workspace переданої задачі видалили без PR, Mako скасує її сам.
  Перетягніть картку з «Нових» у «В роботі», щоб взяти задачу, або з «Помилки», щоб повторити.
  На картках кнопки «Взяти», «Відкласти», «Термінал», «Зміни», «Повторити» і посилання на PR,
  годинник «🕐 Наступний пошук задач через 0:42» з результатом останнього пошуку і кнопкою «Перевірити зараз»
  (або пояснення, чому Mako зараз не шукає: ліміт WIP чи пауза);
- **«+ Задача»** на дошці: задача для агента без трекера (що зробити, подробиці, репозиторій, виконавець).
- **«Спершу план»** (у «+ Задача», «Взяти ▾», «Повторити ▾»): агент спершу пропонує план. Claude у терміналі Mako
  робить це в режимі плану й питає в терміналі; для інших виконавців план зʼявляється на картці «План готовий»
  з кнопками «Погодити», «Переплануй з урахуванням…» і «Відхилити». Погоджений план іде в промпт агента.
- **«Статистика»:** скільки взято, зроблено й змерджено, частка вдалих, медіанний час від «Взяти» до готово й до мерджу,
  вартість фонових запусків, задачі по тижнях, розріз за репозиторієм і виконавцем, найчастіші причини невдач.
- **Пошук на дошці:** за номером, назвою, репозиторієм, виконавцем чи міткою; клавіша `/` — до поля пошуку, `Esc` — очистити.
- **Шаблони задач** (Налаштування → «Шаблони й памʼять»): готові інструкції для задач, що повторюються
  («розібрати нічний ран», «полагодити флейк»). Підходять за мітками або словами в назві, у «+ Задача» вибираються явно,
  і додаються до промпта агента.
- **Памʼять репозиторіїв:** після кожної завершеної задачі Claude дописує в нотатки репозиторію те, що агент дізнався
  (команди тестів, структура, домовленості, підводні камені), і наступний агент у цьому репозиторії отримує їх одразу.
  Переглянути й виправити: сторінка `/memory` (посилання в Налаштуваннях); вимкнути: `"memory": false`.
- **«Налаштування»:** трекери, репозиторії, виконавці, секрети. Зміни застосовуються на льоту.

Інтерфейс доступний лише з вашого компʼютера. `--no-open` вимикає автоматичне відкриття браузера при першому запуску.

**Ctrl+C** зупиняє агентів. Перервані задачі після перезапуску повертаються в чергу, а не позначаються помилкою.

**Логи і промпти** для кожної задачі лежать у `.mako/logs/`. Для `claude-headless` це повний потік подій Claude у форматі JSONL.

## Рецепти

<details>
<summary><b>Jira + Orca: бачити агента наживо</b></summary>

```json
{
  "executors": { "orca": { "type": "orca", "agent": "claude" } },
  "trackers": [{
    "type": "jira",
    "jql": "assignee = currentUser() AND labels = claude-agent AND statusCategory = \"To Do\"",
    "transitions": { "onStart": "In Progress", "onSuccess": "In Review" },
    "projects": { "PROJ": { "repoPath": "/Users/me/code/app" } }
  }]
}
```

Після «Взяти» в Orca відкривається workspace із запущеним Claude. Коли ви відкриєте PR, Mako переведе задачу в In Review.
</details>

<details>
<summary><b>Фонове виконання без питань</b></summary>

```json
"notifications": { "autoTake": true },
"maxConcurrent": 3
```

Підходить для простих задач на кшталт «оновити залежність» чи «виправити опечатку», коли ви лише рецензуєте PR.
</details>

## Безпека

- **Дозволи агента.** У `claude-headless` Claude не може спитати дозволу, тому дозволено лише те, що є в `--allowedTools`.
  `--dangerously-skip-permissions` використовуйте тільки в ізольованому середовищі.
- **Промпт будується з тексту задачі.** Будь-хто, хто може створити задачу з міткою для агента, впливає на те, що агент робитиме.
  Обмежуйте JQL або мітки задачами, які призначені вам (`assignee`).
- **Секрети** лежать лише в `.env` (права `600`), а він у `.gitignore`. Токени не повертаються в браузер після збереження.
- **Вебінтерфейс** слухає тільки `127.0.0.1` і приймає лише запити з `Host: 127.0.0.1` або `localhost`, що захищає від DNS rebinding.
  Кожна зміна вимагає токена, який генерується при кожному запуску. Так інші сайти у вашому браузері не можуть
  змінити налаштування чи взяти задачу. Термінал (WebSocket) додатково перевіряє `Origin`,
  а кожна сесія має власний токен для хуків.

## FAQ

**На macOS сповіщення без кнопок.** У System Settings → Notifications → terminal-notifier оберіть стиль **«Оповіщення» (Alerts)**.
Відповісти завжди можна і на дошці «Задачі».

**На Linux немає кнопок.** Потрібен `notify-send` з libnotify 0.7.9+ (Ubuntu 20.10+, Fedora 33+).

**Mako не бачить задачу.** Запустіть `--dry-run`: там видно, чи задача знайдена і чому її пропущено,
наприклад `project … is not in config` або `no repo matched`.

**Термінал пише «posix_spawnp failed».** Mako виправляє це сам. Якщо помилка лишилась, перевірте дві речі.
Перша: `npm install` має пройти без помилок, бо після нього `scripts/postinstall.cjs` повертає право на виконання
`spawn-helper` з `node-pty`. Друга: команда агента має знаходитись (`which claude`); інакше вкажіть повний шлях
у Налаштуваннях → «Хто виконує задачі» → «Команда агента».

**«Orca CLI не знайдено».** CLI постачається разом із застосунком Orca. Mako шукає його в PATH, у `/usr/local/bin`
і всередині `Orca.app`, а на Linux шукає `orca-ide`. Якщо не знаходить, зареєструйте CLI в Orca (Settings → General → Orca CLI)
або вкажіть шлях у виконавця Orca. Якщо Orca вам не потрібна, перевірте, який виконавець вибрано для репозиторію
(Налаштування → репозиторій → «Хто виконує»).

**Як перезапустити задачу?** Натисніть «Повторити» на дошці «Задачі» або видаліть її запис із `.mako/state.json`.

**Куди поділися worktree?** Вони залишаються після завершення, щоб зміни можна було переглянути.
Щоб прибрати, перенесіть задачу в архів і натисніть там «Видалити»: Mako видалить worktree й локальну гілку
(гілка на сервері і MR лишаються).

## Структура проєкту

```
src/
├── index.ts            # точка входу CLI
├── desktop.ts          # застосунок у рядку меню (Electron): трей, вікно, сповіщення
├── runtime.ts          # спільний запуск Mako для CLI і застосунку
├── orchestrator.ts     # цикл опитування, черга, життєвий цикл задачі
├── review-desk.ts      # PR/MR: створення, CI, треди, конфлікти, мердж, відповіді в тредах
├── tracker-sync.ts     # призначення, закриті й видалені задачі, PR переданих задач
├── planning.ts         # план до коду, шаблони, памʼять репозиторіїв (memory.ts, plan.ts)
├── stats.ts            # сторінка «Статистика»
├── config.ts           # завантаження й перевірка конфігу
├── routing.ts          # вибір репозиторію для задачі
├── prompt.ts           # промпт для агента
├── notify.ts           # сповіщення з кнопками (macOS / Windows / Linux)
├── app.ts              # життєвий цикл конфігу: перший запуск, збереження, застосування на льоту
├── web.ts              # локальний вебінтерфейс і його API
├── inbox.ts            # дошка «Задачі»
├── state.ts            # стан на диску
├── sessions.ts         # живі термінальні сесії та статуси з хуків Claude
├── git.ts              # worktree, назви гілок, push, PR/MR
├── commit-message.ts   # commit message, назва й опис MR, підсумок задачі (Claude)
├── markdown.ts         # безпечний Markdown для описів і підсумків
├── onboarding.ts       # майстер першого запуску: перевірка середовища, пошук клону
├── reviews.ts          # пошук PR/MR для переданих задач
├── trackers/           # jira, github, gitlab
└── executors/          # terminal, claude-headless, orca, command
ui/                     # дошка, сесія, зміни, налаштування, майстер (чистий JS, без збірки), стилі
test/                   # node:test: юніт-тести, повний цикл на справжніх git-репозиторіях, вебінтерфейс, сесії
assets/                 # іконки застосунку і рядка меню
```

Новий трекер реалізує інтерфейс `Tracker` (`src/types.ts`), а новий виконавець реалізує `Executor` (`src/executors/types.ts`).

```bash
npm run typecheck
npm test          # юніт-тести і повний цикл: трекер → агент → push → статуси → мердж
npm run build
```
