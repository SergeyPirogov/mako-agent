# 🦈 Mako

Mako стежить за задачами в GitLab, GitHub і Jira, віддає взяті задачі агенту в Orca й веде їх у трекері:
в роботі, на рев'ю після MR, готово після мерджу. Один бінарник на Go ~10 МБ, ~10 МБ пам'яті.

> Mako — найшвидша акула. Помічає задачу першою і віддає її тому, хто її зробить.

## Що робить

1. Шукає в GitLab, GitHub і Jira Cloud задачі, призначені на вас (з міткою-тригером або всі; з `allProjects` — з усіх проєктів).
2. Показує їх на дошці в браузері (`http://127.0.0.1:7777`) і в системних сповіщеннях.
3. «Віддати в Orca»: клонує репозиторій, якщо його ще немає (`~/mako/projects/<name>`), призначає задачу на вас,
   ставить статус In progress і створює workspace в Orca з агентом, задачею й інструкцією. Гілка `feature/…` для
   задач, `fix/…` для багів і GitLab Issue.
4. Коли з гілки відкрито MR/PR: коментар у задачі з посиланням, статус рев'ю (`transitions.onSuccess`), порожній опис MR
   дописується з diff гілки (`claude -p --model haiku`).
5. Після мерджу: статус Done, і задача закривається. MR закрито без мерджу → «Не виконано».
6. Завершені задачі йдуть в архів через `archiveAfterDays` (2 дні).
7. Стежить за агентом в Orca (`orca worktree ps`, кожні 10 с) — і в чаті Orca, і в терміналі: в картці видно стан
   («працює» з поточним інструментом, «чекає на вас», «закінчив», «зупинився»), останнє повідомлення агента, а для
   агента в терміналі — його екран. Коли агент чекає на вас, закінчив або зупинився — сповіщення, помаранчевий стан
   на дошці й у меню. Коли з'являється MR, Mako пише підсумок роботи з останнього повідомлення агента та змін гілки;
   з `orca.summaryComment` — і в коментар до задачі.
8. На Mac дошка й налаштування відкриваються у власному вікні Mako (системний WebKit, як у Safari): поки вікно
   відкрите, Mako є в Dock і ⌘Tab; закрите — знову лише значок у рядку меню. Запуск Mako з Finder, Launchpad чи Dock (і повторний, коли Mako
   вже працює) показує дошку; запуск при вході в систему — ні. Посилання на MR і задачі відкриваються
   в браузері; «Відкрити в браузері» є в меню значка. На Linux і Windows — браузер.
9. Значок у рядку меню (у треї на Linux): нові задачі й ті, що в Orca, «Відкрити дошку», «Налаштування…»,
   пауза пошуку, запуск при вході в систему.
10. Налаштування (`/settings`): трекери й токени, перевірка підключення, проєкти, статуси, Orca, коментарі в задачі
   (`comments.onStart`, `comments.onReview`: за замовчуванням «Взяв задачу в роботу. Гілка {branch}. Як буде готово,
   відкрию MR.» і «Відкрив MR: {mr}»), ліміти.
   Зміни діють одразу, без перезапуску.

**Замість Orca — термінал Mako** (Налаштування → Агент → «Claude Code у терміналі Mako»). Mako сам створює worktree
(`<папка проєктів>/.worktrees/<repo>/<задача>`) і гілку, запускає в ньому `claude` з тим самим промптом, а на дошці
у вкладці «Термінал» видно живий термінал агента: можна читати, відповідати й підтверджувати дозволи. Стан агента
(працює, чекає на вас, закінчив) приходить з хуків Claude Code. Далі все як з Orca: агент пушить гілку й відкриває MR,
Mako веде задачу. Агенти в терміналі живуть, поки працює Mako; після перезапуску — «Продовжити в терміналі»
(`claude --continue` у тому самому worktree).

Гілки, як в Orca: задача починається від гілки проєкту з «Від гілки» в налаштуваннях (порожньо — основна гілка
origin), новий worktree готує команда «Підготовка» проєкту, загальна з налаштувань агента або вгадана з lockfile
(`pnpm install`, `npm ci`, …) — вона йде в терміналі перед агентом. Справа від термінала — гілка: наскільки вона
позаду основної (✨ — агент робить rebase), що не запушено й не закомічено, Finder і редактор; під нею — MR: CI,
коментарі, конфлікти (✨ — агент виправляє), «Оновити MR» і «Змерджити». Після мерджу Mako прибирає worktree і
локальну гілку, якщо в них немає незакомічених змін.

Плану, автопілота й шаблонів тут немає.

## Запуск

```sh
cd go
go build -o mako ./cmd/mako
./mako -open        # -no-tray: без значка в меню
```

Перший запуск без налаштувань відкриває сторінку налаштувань. Другий запуск не стартує ще одну копію, а відкриває дошку.
Журнал — у `.mako/mako.log`.

## Mako.app для Mac

```sh
go/packaging/mac/build-app.sh 0.3.0   # → go/dist/Mako.app і Mako-0.3.0-mac.zip
```

Універсальний бінарник (Apple Silicon + Intel), у рядку меню. Підпис ad-hoc, без нотаризації:
перший запуск — правий клік → «Відкрити». CI збирає його на кожен тег `v*` (`release.yml`) і прикріплює до релізу.

**Новий реліз:** `git tag v0.3.0 && git push --tags`.

## Налаштування

`mako.config.json` і `.env` у `MAKO_HOME`, `~/.mako` або папці застосунку (`~/Library/Application Support/Mako`);
приклади — `mako.config.example.json` і `.env.example`. Стан — у `.mako/state.json` там само.

Токени в `.env`: `GITLAB_TOKEN` (scope `api`), `GITHUB_TOKEN` (або вхід через `gh auth login`),
`JIRA_EMAIL` + `JIRA_API_TOKEN` (+ `JIRA_BASE_URL`). Для задач з Jira MR шукаються на хості `origin` репозиторію
з `GITLAB_TOKEN` або `GITHUB_TOKEN`.

## Розробка

```sh
cd go && go vet ./... && go test ./...
```

Тести ганяють диспетчер на імітації GitLab (httptest), а Orca — на фейковому скрипті.
