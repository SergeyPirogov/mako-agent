# Як долучитися до Mako

Дякуємо, що хочете допомогти! Коротко про те, як ми працюємо.

## Задача й гілка

- Почніть із задачі в [Issues](https://github.com/SergeyPirogov/mako-agent/issues): опишіть проблему або ідею,
  якщо задачі ще немає.
- Гілка від `main`, одна задача — один PR.

## Код і перевірки

Збірка, запуск і всі перевірки описані в [docs/development.md](docs/development.md). Перед PR у `go/` мають
проходити ті самі перевірки, що й у CI:

```sh
cd go
gofmt -l . && go vet ./... && go test -race ./...
go run honnef.co/go/tools/cmd/staticcheck@v0.8.2 ./...
go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...
```

- Кожна нова чи змінена поведінка (маршрут, гілка, ключ перекладу, виправлення помилки) має тест у тому ж PR,
  зокрема на обробку помилок. Де тестів немає (шаблони, фронтенд, скрипти), опишіть ручну перевірку в PR.
- Тексти для людей — через `internal/i18n` (англійська й українська).

## Коміти й PR

- Перший рядок коміту — до 72 символів, наказовий спосіб, з номером задачі:
  `SergeyPirogov/mako-agent#123: Fix pagination size in the stubs admin`; далі порожній рядок і 1–5 пунктів, що й чому.
- В описі PR: що змінено, як перевірено, на що варто глянути, і `Closes SergeyPirogov/mako-agent#123`.
